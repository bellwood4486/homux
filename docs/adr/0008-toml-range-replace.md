# 0008. `.homux.toml` は `profiles` 配列だけを範囲置換する

## 状況

`profile create` / `rename` / `delete` は `.homux.toml` の `profiles` を書き換える。

一方 `init` は、新規リポジトリ向けに `ignore` の候補（`README.md`、`LICENSE`、`docs/**`）を**コメントアウトした状態**で含む雛形を生成する。

## 決定

読み取りは `go-toml/v2` の `Unmarshal` を使う。

**書き込みでは全体を Marshal しない。** `profiles = [` の開始位置から対応する `]` までのバイト範囲だけを特定して置換し、ファイルの他の部分（`ignore` セクション、ユーザーが書いたコメント、整形、キーの順序）には一切触れない。

## 却下した案

### Unmarshal → Marshal で書き戻す

**`profile create` を 1 回実行しただけで、`init` が生成した雛形のコメントが消える。** ユーザーが自分で書いたコメントや、意図的なキーの順序も失われる。

CLI がリポジトリを変更した結果が、ユーザーの意図と無関係に正規化されてしまうのは INV-10（CLI が repository を変更しても、結果は CLI なしで理解可能であること）に反する。

### `go-toml/v2` の `unstable` パーサで AST とバイト位置を取り、該当ノードだけ書き換える

厳密ではあるが、`unstable` と明示された API に依存する。得られる精度の差（`profiles` 配列**内部**のコメントを保持できるかどうか）が、そのリスクに見合わない。

## 帰結

- `profiles` 配列の**内部**に書かれたコメントは失われる。spec §15 に既知の制限として記載する
- `profiles` 配列の書式は homux が生成する形（1 要素 1 行）に正規化される
- `.homux.toml` の他のすべての内容は保存される
