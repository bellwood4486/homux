# 0014. 走査起点に `$HOME` 直下の symlink を加え、受容する検出漏れをトップレベルのディレクトリ削除だけに絞る

ADR 0004 の範囲を絞り込む。

## 状況

ADR 0004 は Stale 種類2（source が消えたのに残った managed symlink）の走査起点を
「repo のトップレベルエントリに対応する HOME パス」に限定し、そこから再帰することにした。

重要なのは、**repo 由来の判断はこの起点の集合を作る 1 回だけ**だという点である。
起点が 1 つ立てば、その配下は `os.ReadDir` で無条件に再帰され、repo の構造とは無関係に全部歩かれる。
したがって検出漏れは各階層に現れるのではなく、**トップレベルに 1 本だけ**開いている。

| repo から消したもの | HOME 側の残骸 | ADR 0004 時点 |
|---|---|---|
| `.config/nvim/`（2 階層目以降） | `~/.config/nvim/init.lua` | `~/.config` が起点として残るので検出できる |
| `.zshrc`（トップレベルのファイル） | `~/.zshrc`（symlink） | 起点が消えるので**見逃す** |
| `.config/`（トップレベルのディレクトリ） | `~/.config/**` の symlink 群 | 見逃す |

2 行目が問題である。repo からの削除は spec §16 が勧める通常の操作（`rm foo@@work`）であり、
その直後に案内される `status` が、宙に浮いたリンクを抱えたまま "clean" と答えてしまう。

## 決定

**走査起点を、repo のトップレベルエントリ由来の集合と `$HOME` 直下の symlink の和にする。**

`$HOME` 直下は `ReadDir` するだけで、**実ディレクトリには降りない**。
加えるのは `fs.ModeSymlink` を持つエントリのみで、判定は既存の symlink 評価にそのまま渡す。
起点は repo 由来と重複しうるので、集合として重複を除く。走査コストは `ReadDir` 1 回分しか増えない。

これで上表の 2 行目が塞がる。1 行目は変わらず検出できる。

**3 行目（トップレベルのディレクトリ削除）の検出漏れは引き続き受容する。**
ADR 0004 が受容した範囲は、この 1 パターンだけに絞られる。

## 却下した案

### `$HOME` 全体、あるいは `$HOME` 直下の実ディレクトリすべてを起点にする

上表 3 行目を塞ぐには `~/.config` を起点に加えるしかなく、それは
「`$HOME` 直下のエントリすべてを起点にする」ことと区別できない。
`~/Library`、`~/.cache`、`~/.rustup`、`~/node_modules` を抱えることになり、
ADR 0004 が却下した HOME 全走査そのものになる。opt-in フラグ（`--scan-home`）として
提供する案も検討したが、実際に困る事例がまだ無いので取り下げた。

### かつて起点だったパスを記録しておく

「repo に `.config/` があった」を覚えておけば 3 行目も塞げるが、
それは manifest / state file の導入であり ADR 0003 に正面から抵触する。

### 先行事例

- **yadm** の alternates は `remove_stale_links()` で残骸を掃除するが、候補を `git ls-files -- '*##*'` から作るため、source を完全に消すと候補から落ちる。**同じ穴が開いている**
- **chezmoi** は既定で symlink ではなく実ファイルを書くため、残骸が「中身の入った正しいファイル」になり痕跡が残らない。答えは検出ではなく利用者の宣言（`remove_` プレフィックス / `.chezmoiremove`）

状態 DB を持つ実装が 2 つあって、どちらもこの穴を状態では塞いでいない。ADR 0003 は本件で何も失っていない。

## 帰結

- 受容する検出漏れは「repo のトップレベルにあるディレクトリを削除した場合」だけになる
- 残る 1 パターンを利用者に伝える責任が生じる。spec §15 と README に明記する。**塞いだ分だけを宣伝して、残り 1 つを黙っているのが一番まずい**
- `$HOME` 直下の symlink が起点に加わっても、spec §8.2 の暗黙除外（`.git` / `.homux.toml`）は起点にならない
- repo 自身が `$HOME` 配下にある配置（BEL-20）への影響は無い。repo の親は実ディレクトリなので、この経路では起点にならない
- 検出した残骸を homux が削除することはない。報告に留める（INV-13 / INV-14）
