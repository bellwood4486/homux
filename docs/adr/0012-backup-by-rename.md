# 0012. 退避は同一ディレクトリ内の rename 一本とし、退避先は plan が決める

## 状況

`apply` は Occupied な target（unmanaged な HOME 上のファイル・ディレクトリ・repo 外を指す symlink）を退避してから symlink を張る。退避を必ず残すことは INV-13 が要求している。

退避先は `<name>.homux-bak.<timestamp>` で、timestamp は秒単位である。この経路には設計上の制約が 2 つある。

- `plan` は `os` を import できない（`docs/design.md` §2.1）。したがって**退避先が既に存在するかを検査できるのは `exec` だけ**である
- `apply --dry-run` は `plan` までしか進まないため、dry-run が示した退避先は「その名前で退避する予定である」以上のことを保証しない

## 決定

退避は**同一ディレクトリ内の `rename` 一本**とする。対象が通常ファイルでもディレクトリでも repo 外を指す symlink でも規則は変わらない。

**退避先は `plan` が決定論的に決める。** `exec` は与えられた退避先が既に存在すればその target を変更せず停止し、空いている名前を探さない。

## 却下した案

### 退避先が衝突したら連番を振る（`...homux-bak.20260905-153000.2`）

「空いている名前を探す」とは、**ファイルシステムを読んで退避先を決める**ということである。それができるのは `exec` だけなので、退避先の決定権が `plan` から `exec` へ移る。

結果として 2 つが壊れる。dry-run が表示した退避先と実際の退避先が食い違いうること、そして `Action.Backup`（`plan` が必ず埋める。INV-13 の担保）が「最終的な退避先」ではなく「最初に試す候補」に意味を変えることである。衝突は同一秒内に同じ target を 2 回退避したときにしか起きず、その稀さに対して払う代償として大きすぎる。

### timestamp をミリ秒・ナノ秒にする

衝突確率を下げるだけで、衝突したときの規則は依然として必要になる。決めるべき問いを先送りしつつ、プロンプトに出るパスを読みにくくするだけである。

### 退避先の衝突を「スキップして続行」にする

spec §12.4 の Error 状態（unknown profile / ambiguous など）と同じ扱いにする案。

Error 状態は**適用を始める前**に判明し、その target が最初から対象になりえないことを意味する。退避先の衝突は**既に HOME を変更し始めた後**に判明する。後者を握り潰して続行すると、INV-13 の「必ず退避を残す」が守られた target と守られなかった target が同じ実行の中に混ざり、結果から区別できなくなる。

### ディレクトリの退避を禁止し、Error に落とす

「既存**ファイル**を退避」という元の文言に忠実な案。

しかしこれを選ぶと、`~/.claude/settings.json` がディレクトリになっている状態を homux 自身では永久に解消できない。ユーザーは手で退けるしかなく、これは「専用コマンドを増やさず診断・可視性・安全性を強化する」（spec §16）ではなく、単に手詰まりを作ることである。

同一ディレクトリ内の rename は中身の量に依らず一定時間で終わり、コピーしないので内容もパーミッションも変わらない（ADR 0006 と整合する）。ディレクトリを特別扱いする技術的な理由がない。

## 帰結

- `apply` を同一秒内に 2 回実行し、同じ target が 2 度 Occupied になった場合、2 回目は停止する。再実行すれば収束する
- `apply --dry-run` は退避先の衝突を検出できない。dry-run が何も問題を示さなくても `apply` が途中停止することはありうる（spec §12.5 に記載）
- ディレクトリを退避した場合、`.homux-bak.<timestamp>` はディレクトリのまま残る。homux はそれを消さない
